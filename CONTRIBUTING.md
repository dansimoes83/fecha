# Contributing

F.E.C.H.A. is intentionally small.

Contributions should make the framework easier to understand, apply, or test without turning it into a full product methodology or a generic productivity system.

## Good contributions

- clearer examples;
- edge cases;
- accessibility improvements;
- translations that preserve the original step names;
- tool usage guides that do not redefine the framework;
- better templates;
- corrections to ambiguous language.

## Avoid

- renaming the five canonical steps;
- forcing F.E.C.H.A. onto every interaction;
- adding process layers that turn it into a full methodology;
- inventing ownership or timelines;
- treating speed as the goal;
- turning the framework into a scoring system.

## Source of truth

Changes to the method belong in:

`framework/fecha.md`

Changes to AI behavior belong in:

`instructions/fecha-instructions.md`

Tool guides should point to those files rather than redefining the framework.

## Pull requests

A useful pull request should explain:

1. what problem it solves;
2. whether it changes the framework or only its implementation;
3. what must remain unchanged;
4. an example showing the improvement.
